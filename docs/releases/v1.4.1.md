## 1. 背景

v1.4.0 只交付了 Python 单运行时。本版把同一套 HTTP/SSE 契约落到 Java 企业栈，作为双语言 Runtime 的学习与验证载体；同时补齐期间确认的工作区权限档位、MCP 凭据体验、Skills 与上下文使用量展示，并把验收从“契约能通”推进到“行为一致 + 双 UI E2E”。

## 2. 变更内容

### 2.1 Java Runtime（新增 `backend-java/`）

- Spring Boot 3.5 + Spring MVC SSE + MyBatis-Plus + Flyway + MySQL 8.4；独立数据库与容器，不调用 Python 后端。
- 契约同形：snake_case、ISO-8601 `Z`、错误信封、`X-Request-ID`、Bearer 401、SSE `event/id/data`、15s 心跳、终态关流、全局事件 id。
- 端点覆盖除刻意差异外的全部 1.4 契约：Session/Run/Message/ToolCall、取消/超时/恢复、工作区与文件工具、压缩与轨迹、Model Profile（含 `probe`）、MCP Client（官方 SDK：stdio + Streamable HTTP）、Skills、`GET /tools`、`GET /sessions/{id}/context`。
- 部署：compose 新增 `backend-java`、`ui-java`、`mysql-java`；`linux/amd64`；数据卷与 Python 隔离，`skills/` 唯一只读共享。

### 2.2 工作区与权限档位（两端）

- 命名工作区：同名自动加后缀；输入目录即项目，会话归到项目下。
- 权限档位 `read_only / workspace_write / full_access`，默认 `workspace_write`；`full_access` 需二次确认。
- 文件工具增加 `file_delete`（可删空目录）、`file_search` 等；新增 `reindex`/`file`/`search`/`tree` 端点，工作区根目录挂到数据卷 `/workspaces`。

### 2.3 MCP 凭据与 K-09

- MCP `env`/`headers` 可在 UI 直接填写并明文入库；接口只回 `***` 与键名；`${ENV_VAR}` 占位继续支持；任何日志/SSE/轨迹不回显凭据。
- 取消逐工具审批（K-09）：权限档位即策略，`requires_approval=false`；Java 不注册 approval/preview 端点，事件总数 24（Python 保留端点但不再触发）。

### 2.4 Skills（两端对齐）

- 只读技能包：`SKILL.md` + `references/scripts/assets`；多根目录、同名 `shadowed`、5s 缓存。
- `GET /skills`、`GET /skills/{name}`；Run 支持 `skill_name`，注入 `skill_context` 消息并把 `<available_skills>` 清单加入 system prompt；`skill` 工具按需读取正文/资源（防越界、60k 上限）。
- 共享示例技能 `skills/skills/prism-demo`。

### 2.5 上下文使用量展示

- `GET /sessions/{id}/context`：窗口/预算/已用/百分比/阈值/可压缩/上次压缩。
- UI 在输入框下方显示进度条与 `上下文 42% · 12k/29k`，≥85% 标红并提供「压缩上下文」；每 15s 刷新。
- Session ID 改为标题下方副标题 + 复制按钮。

### 2.6 验收工具

- `tests/parity`：6 个双端行为对照（文本、工具回环、技能注入、BUSY+取消、重放、上下文），确定性 mock 模型，`scripts/run-parity.sh` 一键复现。
- Playwright `playwright.ui-parity.config.ts` + `parity.live.spec.ts`：同一 spec 跑 `:3000` 与 `:3001`。
- parity 表新增 Known Differences（K-09、`workspaces/pick`、FTS、token 估算器）。

## 3. 兼容性

- Python 无数据库迁移（`alembic` 无新 revision）；对外仅**新增**端点与可选字段。
- 行为变化：MCP 工具不再逐次审批；未绑定的审批流程不会再出现（K-09，已确认）。
- Java 首次启动自动 Flyway 迁移 V1–V6；需要 JDK 21 镜像与 MySQL 8.4；不影响 Python 数据。
- `full_access` 仅 UI 二次确认，不做自动审查。

## 4. 升级步骤

```bash
git fetch --tags && git checkout v1.4.1
cd backend && uv sync                 # Python 依赖
cd ../ui && pnpm install --frozen-lockfile && pnpm build
```

双运行时（服务器 `192.168.31.90`，禁止本机 Docker Desktop）：

```bash
rsync -az --exclude .git --exclude '.env' ./ srv:~/prism-agent/
ssh srv 'cd ~/prism-agent && docker compose build && docker compose up -d --no-build'
```

- Python：`:3000` UI / `:8000` API；Java：`:3001` UI / `:8001` API；MySQL 不对外发布。
- 工作区卷 `workspace-python` / `workspace-java` 独立；`skills/` 共享只读。

## 6. 已知问题 / 刻意差异

- K-09：无逐工具审批；Java 无 `approval`/`preview` 端点与 3 个审批事件（事件总数 24 vs 27）。
- Java 不提供 `POST /workspaces/pick`（UI 已改为输入目录）。
- Java 无 FTS5：`workspace_fts=unsupported`，检索为关键字扫描，返回结构一致但排序/相关度可能不同。
- token 估算器 tiktoken（Python）vs jtokkit（Java），数值允许偏差；契约只断言阈值与相对高低。
- 行为 parity 未覆盖：超时/恢复、压缩、MCP、权限档位 E2E、Model Profile 行为对比（parity 表保持 Pending）。
- 部署版 STDIO MCP 的 `uvx` 冷启动受网络影响，E2E 未覆盖；语言内 `McpConnectionTest` 已通过。
