## 1. 背景

v1.3 之前，长会话只能直接丢弃最旧消息，模型从此失忆；同时无法回答"每一步模型看到了什么、花了多少 token"，模型也只能由 `.env` 固定。V1.4 补齐三件事：上下文压缩、轨迹、Model Profile，并明确 1.x 到此收口。

## 2. 变更内容

### 2.1 上下文压缩

- 每个 Step 组装前先做**确定性裁剪**：超过 8000 字符的 tool 结果保留头尾各 2000，中间插入 `…(pruned N chars)…`；只改发送副本。
- 估算输入 token，超过预算 85% 时选最旧一段（保留约 20k tokens 或预算 20%，不切断 assistant/tool 配对）生成 **8 段结构化摘要**。
- 摘要写入 `compaction_checkpoints`，后续请求只带 `first_kept_message_id` 之后的消息 + checkpoint；**原文一条不删**，轨迹可回放。
- 重复压缩把旧摘要作为输入增量合并；失败记录 `compaction.failed` 并继续，不写半成品。
- provider 报上下文溢出时强制压缩一次并重试；仍超出 100% 才由 Assembler 丢弃最旧非保护单元。
- 会话空闲时可点「压缩上下文」或调 `POST /sessions/{id}/compact`；运行中返回 `COMPACTION_BUSY`。

### 2.2 轨迹

- 新增 `step.started/completed/failed`、`context.pruned`、`compaction.started/completed/failed/skipped` 事件；`ModelResponse` 增加 `finish_reason`。
- 新增 `GET /sessions/{id}/trajectory`：按 Turn → Step → Tool 返回模型、usage、耗时、stop reason、工具与压缩记录，支持 `limit/before`。
- 旧 Run 无 Step 事件时合成一个 `legacy` Step，usage 为空并明确标注。
- 会话内新增独立「轨迹」Tab（`/sessions/:id/trajectory`），含记录 inspector、运行中 2 秒轮询、加载更早。
- 执行详情**瘦身**：只保留工具名、参数、结果、状态、单次耗时；Run 状态/错误/审批提示移到轨迹。

### 2.3 Model Profile

- 新增 `model_profiles` 表：名称、base_url、model、`api_key_env`、context window、max output；全局唯一 active。
- 独立「模型」页支持新增/编辑/删除/测试连接/切换；切换后**下一次请求**起对所有会话生效，运行中的 Step 不变。
- Run 创建时快照 `model_profile_id/model/context_window/max_output`；Provider 与 Assembler 按 Run 解析。
- 密钥只保存环境变量名，明文从后端进程环境读取；缺失时创建 Run 前返回 422，不落库。
- 没有档案时回退 `.env` 的 `MODEL_*` 配置，行为同 v1.3。

### 2.4 数据与迁移

- `runs` 新增 `model_profile_id`（SET NULL FK）、`model_context_window`、`model_max_output_tokens`。
- 新增 `model_profiles`、`compaction_checkpoints` 表及索引。
- 迁移 `20261127_0007`，支持 upgrade/downgrade 往返。

### 2.5 Java 双运行时 Runtime

- 新增 `backend-java/`：Spring Boot 3.5 + Spring MVC SSE + MyBatis-Plus + Flyway + MySQL 8.4，与 Python 完全独立的库、容器与运行状态；不通过 HTTP 调用 Python。
- 对外契约与 Python 1.4 同形：统一 snake_case、ISO-8601 `Z`、错误信封 `{error:{code,message,request_id,details}}`、`X-Request-ID`、Bearer 401、SSE `event/id/data` 与 15s 心跳、终态关流、事件 `id` 为全局事件 id。
- 功能面：Session/Run/Message/ToolCall、取消/超时/恢复、工作区与文件工具（三种权限档位）、压缩与轨迹、Model Profile（含 probe）、MCP Client（官方 SDK，stdio + Streamable HTTP，凭据 `***` 掩码）、Skills（只读目录、Run 注入、`skill` 工具）、`GET /tools`、`GET /sessions/{id}/context`。
- 部署：compose 服务 `backend-java`、`ui-java`、`mysql-java`；`skills/` 为两端唯一只读共享挂载，工作区与数据库卷隔离；镜像 `linux/amd64`。
- 已知刻意差异见 §6（审批 K-09、目录选择器、FTS、token 估算器）。

### 2.6 上下文使用量展示

- 新增 `GET /sessions/{id}/context`：`context_window/max_output_tokens/budget_tokens/used_tokens/percent/threshold/needs_compaction/compactable/last_compaction`。
- 预算 = `max(1024, window - max_output - 2048)`；有 checkpoint 时按 `tokens_after + 其后消息估算`，否则估算全部消息；窗口取会话最近 Run 快照，缺失时用配置默认。
- UI 在输入框下方显示进度条与 `上下文 42% · 12k/29k`，≥85% 标红并出现「压缩上下文」（二次确认 → `POST /sessions/{id}/compact` → 刷新）；每 15s 刷新。
- 两端估算器不同（tiktoken / jtokkit），契约只断言预算公式、`used>0` 与阈值/相对高低。

## 3. 兼容性

- Python：需要执行迁移：`cd backend && uv run alembic upgrade head`；旧会话、旧 Run 全部兼容。
- 无破坏性 API 变更：新增可选字段/接口；`RunInspector` 的展示范围收窄为工具明细。
- Python 不新增第三方依赖（继续使用 OpenAI-compatible SDK、SQLite、tiktoken）；Skills 与 MCP 依赖已在 V1.2/V1.3 引入。
- Java：Flyway 在启动时自动迁移（V1–V6），需要 JDK 21 镜像与 MySQL 8.4；卷 `workspace-java`、`skills` 只读挂载；不影响 Python 数据。
- 无档案时行为与 v1.3 完全一致（两端均回退 `MODEL_*` 配置）。

## 4. 升级步骤

```bash
git pull
cd backend && uv sync && uv run alembic upgrade head
cd ../ui && pnpm install --frozen-lockfile && pnpm build
```

重启后端与 UI（`./scripts/dev.sh` 会自动跑迁移）。如需使用档案，在「模型」页新增并切换；确保 `api_key_env` 指向的环境变量已在后端进程中设置。

双运行时部署（服务器 `192.168.31.90`，禁止本机 Docker Desktop）：

```bash
rsync -az --exclude .git --exclude '.env' ./ srv:~/prism-agent/
ssh srv 'cd ~/prism-agent && docker compose build && docker compose up -d --no-build'
```

- Python：`:3000` UI / `:8000` API；Java：`:3001` UI / `:8001` API；MySQL 不对外发布。
- `skills/` 为共享只读挂载；示例技能 `skills/skills/prism-demo` 可用于验收技能菜单与注入。

## 6. 已知问题 / 遗留

- 档案的 `api_key_env` 从进程环境读取；只写在 `.env`、未进入 `os.environ` 的变量取不到。
- 旧 Run 没有 usage；轨迹 Step 的 `assistant_message_id` 仍为空，工具按 `tool_call_ids` 归属。
- 手动压缩不记录摘要请求的 usage；其 checkpoint 挂到最后一个 Turn 展示。
- 轨迹暂不做时间轴缩放、虚拟滚动与跨会话搜索。
- 压缩摘要质量依赖当前模型；超长技能/工具输出会被裁剪或摘要，精确原文需回看消息或轨迹。
- 双运行时刻意差异（不追平）：K-09 不做逐工具审批（Java 无 approval/preview 端点与 3 个审批事件）、Java 不提供 `POST /workspaces/pick`、Java 无 FTS5（`workspace_fts=unsupported`，检索为关键字扫描）、token 估算器 tiktoken vs jtokkit。
- 行为 parity 未覆盖：超时/恢复、压缩、MCP、权限档位 E2E、Model Profile 行为对比（parity 表保持 Pending）。
