# V1.4 Implementation Plan（Compaction / Trajectory / Model Profile）

> **For agentic workers:** REQUIRED SUB-SKILL: Use subagent-driven-development (recommended) or executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 交付 1.x 最后一版：上下文压缩（先裁剪后摘要 + checkpoint）、独立轨迹页、全局多档案 Model Profile；执行详情瘦身为工具明细。

**Architecture:** Model Profile 按全局 active 生效、Run 创建时快照；Provider 与 ContextAssembler 按 Run 解析。压缩在 Engine 内、组装前执行：确定性裁剪 tool 结果 → 估算 token → 超阈值用同 Provider 生成结构化摘要 → 写 `compaction_checkpoints` → 以受保护合成消息注入。Step/compaction 事件供轨迹页投影。

**Tech Stack:** Python 3.12、FastAPI、SQLAlchemy 2 Async + aiosqlite、Alembic、Pydantic v2；Vue 3 + zod + Vitest。

**Spec:** `docs/superpowers/specs/2026-11-27-v1.4-compaction-trajectory-model-profile-design.md`

## Global Constraints

- SQLite 唯一库；迁移 `20261127_0007`（model_profiles、runs 三个快照列、compaction_checkpoints）。
- 事件只追加；checkpoint 原文不删；轨迹是投影不是第二事实源。
- `ContextAssembler` 保持同步纯函数；摘要请求与 checkpoint 写入只在 Engine/Application 层。
- checkpoint 与 `skill_context` 都是受保护单元，裁剪不得删除。
- 密钥只存环境变量名（`api_key_env`），不得写库/日志/事件。
- 同一 Run 内模型固定；运行中切换档案不影响当前 Run。
- 压缩后仍超预算才走既有 100% 兜底；只剩受保护单元超预算报 `CONTEXT_BUDGET_EXCEEDED`。
- 后端门禁：`uv run pytest`、`ruff check`、`ruff format --check`、`mypy src`；UI：`pnpm check`、`pnpm test`、`pnpm build`。
- 命令在 `backend/` 用 `uv run`，`ui/` 用 `pnpm`。

## Review Focus

1. **压缩真正生效且 checkpoint 不被裁剪**：压缩后请求只含 first_kept 之后消息 + 摘要；长历史下 checkpoint 仍在（T8、T9、T14）。
2. **Run 快照隔离**：切换档案只影响后续 Run；运行中 Step 不换模型（T3、T4、T14）。
3. **溢出重试有界**：`CONTEXT_OVERFLOW` 只强制压缩重试一次，失败即失败，不循环（T9、T14）。
4. **轨迹的事实一致**：新 Run 用 Step 事件、旧 Run 合成且标 legacy；compaction/trim/prune 行不重复（T11、T12、T14）。
5. **执行详情与轨迹不重叠**：执行详情只剩工具明细，状态/usage/步骤只在轨迹（T13）。
